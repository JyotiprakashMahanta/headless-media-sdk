Architecture

app ──────▶ media-react  ──────▶ media-core
 │          media-native ──────▶ media-core
 └────────▶ media-ui-react     (imports nothing of ours)
            media-ui-native    (imports nothing of ours)
  • Core imports nothing. It compiles with "lib": ["ES2022"], "types": [] — no DOM, no Node, no React. If someone writes document. in it, it does not compile.
  • Wrappers are the only packages that import core. They contain no URLs, no response mapping, no provider knowledge — only React lifecycle work.
  • Components import neither. They are generic over the item type.

npm run check:boundaries fails the build on any violation, checking both declared dependencies and actual import specifiers.

Auth

The API key is passed once and captured in a closure inside the transport layer (src/client/http.ts). It is never stored on an instance property, never returned, never part of a cache key, never in an event payload, and never in an error message or endpoint field.

import { createMediaClient } from 'media-core';

const client = createMediaClient({
  apiKey: process.env.PEXELS_API_KEY,
  // optional
  baseUrl: 'https://api.pexels.com',
  fetch: myFetch,          // inject for tests, proxies, or a CLI
  cache: { ttlMs: 300_000, maxEntries: 200 },  // or `false`
  logEvents: true,         // attaches the console listener
  defaultPerPage: 24,
});
Browser reality check. Pexels has no OAuth and no token exchange, so a browser-only app must ship the key to the client. The design confines it to one module so that pointing baseUrl at your own proxy — and dropping the key entirely — is a one-line change with no other code touched.

For scripts and CLIs there is also a module singleton: configureMedia({ apiKey }) then getMediaClient(). Do not use it from React — it is invisible to tests and leaks across SSR requests. MediaProvider calls createMediaClient instead.

Ids are namespaced — "photo:2014422", "video:2499611" — because the photo and video endpoints have overlapping numeric id spaces.

Return types

  totalResults: number | null;
  hasMore: boolean;
  nextPage: number | null;
}

interface MediaItem {
  id: string;              // "photo:123"
  kind: 'photo' | 'video';
  sourceUrl: string;       // provider page, for attribution
  width: number;
  height: number;
  aspectRatio: number;     // reserve grid space before load
  placeholderColor: string | null;
  alt: string;
  author: { id, name, profileUrl };
  thumbnailUrl: string;    // grid
  previewUrl: string;      // display / playable video
  downloadUrl: string;     // highest quality
  durationSeconds: number | null;
  renditions: readonly MediaRendition[];  // ascending by width
}

These types are ours, not Pexels'. Raw provider JSON exists only inside src/client/pexels.ts. Swapping to Unsplash means writing a sibling of that one file — no hook, component or app code changes.

client.download(item, { surface })

Returns { url, filename, item } and emits download. It does not save a file: core has no DOM. Core owns "which URL and what filename"; the platform owns "how bytes reach disk". That split is why the same call works in a browser, in React Native and in a CLI.

client.trackView(item, { surface })

Emits view. Surfaces used by the demo app: grid, lightbox, reel.

Events

const off = client.on('download', (event) => { /* … */ });
const offAll = client.onAny((event) => { /* … */ });
off();  // unsubscribe — idempotent
EventPayload
view{ item, surface, at }
download{ item, url, surface, at }
search{ query, kind, page, resultCount, at }
error{ code, message, endpoint, at }
  • on() returns an unsubscribe function rather than requiring a matching off() — it drops straight into a useEffect cleanup.
  • Listeners are copied before dispatch, so unsubscribing from inside a listener cannot corrupt the current dispatch.
  • A throwing listener is caught and never breaks the SDK or the other listeners.
  • Payloads never contain the API key. Events are an activity log; analytics sinks have no business seeing credentials.
  • A default console listener is attached unless logEvents: false. The app can subscribe independently at the same time — the demo's Activity panel does exactly that.

Errors

Everything thrown is a MediaError with a code. Branch on the code, never the message.

Cache & de-duplication

One Map solves two problems that share a key:

  1. Caching — the same page inside the TTL does not hit the network twice. Grids remount constantly and Pexels allows 200 requests/hour on free keys.
  2. De-duplication — three components asking for the same page in the same tick send one request and all await it. React 18 StrictMode alone doubles every request in dev without this.
client.cacheStats();  // { size, inflight, hits, misses, deduped }
client.clearCache();

Cache keys sort their params, so ?a=1&b=2 and ?b=2&a=1 share an entry. The API key is deliberately not part of the key — it does not change the response shape, and keys end up in logs. A rejected request is never cached, so a transient failure cannot poison a key.

No localStorage, no IndexedDB: core must run in a worker or a CLI, and persistence is a policy decision belonging to whoever embeds the SDK.

Design notes worth knowing:

  • items is already accumulated across pages. Keeping your own array and concatenating will double every item.
  • loadMore is referentially stable and already no-ops while loading or when hasMore is false.
  • isLoading is first-page-only; isLoadingMore is appending. Using one for both blanks the grid on every page.
  • Event handlers are stored in a ref, so inline arrow functions create exactly one subscription per mount.
  • Stale responses are dropped by a monotonic request token — aborting alone is not enough, since an already-resolved promise can still land after the input changed.
  • Every type the app needs is re-exported, so the app never lists media-core as a dependency.

media-native

Same hook names, same return shapes, so feature code reads identically on both platforms. Two differences:

  • usePagedMedia also returns onEndReached, pre-guarded for FlatList — which fires repeatedly during a fling, unlike a web IntersectionObserver.
  • useMediaDownload uses the OS share sheet (Share.share, falling back to Linking.openURL) instead of an anchor element. Swapping in expo-file-system would change nothing above that line — which is the argument for the core/wrapper split.

react-native is an optional peer dependency and is not installed in this repo. A repo-level typecheck shim (types/react-native.d.ts) declares exactly the RN surface these packages use, so they still typecheck and still fail the build if they drift. See the README for the reasoning.
